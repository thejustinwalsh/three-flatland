Approved for the stacked alpha PR

The private ECS does not become an application API

The published package no longer depends on Koota. Public declarations do not expose the replacement world, entity, trait, registry, or slot-mutation types. The root and React entry points retain their existing export-map shape, while the migration guide and changeset describe every intentional consumer-facing break.

Koota made this design possible. Its typed traits, SoA storage, queries, and systems established the architectural foundation that Flatland specialized for a renderer-owned workload. Koota remains our recommended general-purpose ECS for application and gameplay state; this private renderer path does not supersede it.

This is an alpha-release approval, not a stable-API freeze. One inherited declaration hygiene class remains: @internal members and wildcard helper modules are still type-addressable. They are excluded from generated API docs but should be erased or explicitly stabilized before leaving alpha.

Remaining API work

Stable-release follow-ups

Required before stable

Erase or stabilize remaining @internal declarations

Generated API pages correctly omit internal members, but TypeScript declarations still contain 240 @internal annotations across 28 reachable files. This is mostly inherited renderer plumbing rather than ECS handles, yet a consumer can still name some underscore members. Before the stable API freeze, move cross-module state behind private fields or erased friend seams, or deliberately document the members that become supported.

Required before stable

Replace broad wildcard access to React helpers

./react/* makes internal helper modules importable by path. The new recordBatchRaycastResult helper is marked @internal and excluded from TypeDoc, but remains reachable through three-flatland/react/batchPicking. Enumerate supported React subpaths or move helper modules outside the wildcard before 1.0.

Not a blocker for this alpha stack

Neither finding leaks the private ECS world, entity, trait, registry, or slot ownership model. The wildcard family and broad internal declarations predate this release. The audit records them now so the eventual stable surface is chosen deliberately instead of inherited accidentally.
